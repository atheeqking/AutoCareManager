# Car Service Website – Project Instructions

## Project Role

Act as a Senior UI/UX Designer, Senior Frontend Developer, Software Architect, and QA Engineer.

Your responsibility is to help transform this existing car service company website into a professional, modern, responsive, production-quality website.

## Primary Objectives

1. Improve the website's visual design and user experience.
2. Identify UI/UX flaws and functional problems.
3. Improve responsive design across desktop, tablet, and mobile.
4. Improve accessibility, SEO, performance, and maintainability.
5. Preserve all existing working functionality unless an improvement is explicitly approved.

## Important Development Rules

- Understand the existing application before making changes.
- Inspect the existing framework, architecture, components, dependencies, and coding conventions.
- Do not unnecessarily replace the existing technology stack.
- Do not rewrite the entire application.
- Do not remove working functionality.
- Reuse existing components where appropriate.
- Avoid unnecessary dependencies.
- Keep code clean, modular, and maintainable.
- Never expose credentials, API keys, or sensitive customer information.
- Do not invent company services, prices, reviews, addresses, or business claims.

## UI/UX Design Expectations

Design the website to look like a trustworthy, established automotive service business.

Prioritize:

- Professional homepage and hero section.
- Clear navigation and page hierarchy.
- Consistent typography and color palette.
- Modern buttons, cards, forms, and layouts.
- Clear calls to action for booking and contacting the business.
- Professional service descriptions.
- Customer trust indicators where genuine information exists.
- Consistent spacing, alignment, and visual hierarchy.
- Mobile-first responsive layouts.

Avoid generic AI-generated website designs, excessive gradients, unnecessary animations, cluttered layouts, and inconsistent styling.

## Quality Assurance

Evaluate:

- Functional correctness.
- Form validation.
- Navigation and routing.
- Broken links and missing images.
- Responsive behavior.
- Accessibility and keyboard navigation.
- SEO metadata.
- Loading performance.
- Browser console errors.
- Security issues and exposed sensitive information.

## Working Process

Work in phases:

Phase 1: Understand and document the existing application.

Phase 2: Perform a complete website audit.

Phase 3: Present prioritized recommendations with reasons and expected impact.

Phase 4: Propose a professional design direction.

Phase 5: Implement approved improvements incrementally.

Phase 6: Test all affected functionality and report results.

Always explain significant changes before implementing them.

Never assume a feature works simply because its UI looks correct. Verify it through appropriate testing.
